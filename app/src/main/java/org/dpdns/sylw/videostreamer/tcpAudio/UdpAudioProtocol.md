# UDP 音频传输协议设计文档

## 双重连接机制

音频传输建立两个独立连接，分别用于：
1. **TCP 连接 (可靠性)**：用于握手、配置同步、状态反馈及心跳检测。
2. **UDP 连接 (实时性)**：用于连续的 PCM 音频数据流。

连接状态依 TCP 确认，其中一方断开 TCP 连接即视为音频服务彻底断开。


## 1. 握手与控制阶段 (TCP)
客户端连接服务端 TCP 端口后，首先发送 1 个配置包：
| 字段 | 长度 | 说明 |
| :--- | :--- | :--- |
| **采样率索引** | 1 Byte | 0x01 (48000Hz)  0x00 44100
| **声道数** | 1 Byte | 0x02 (立体声)  0x01 单声道

在收到服务端空包确认后，连接建立。
TCP 链路后续用于：

- 心跳检测与延迟测试：客户端记录（不发送）音频包时间戳，服务端回包依次包含最近一次udp包序号、对应udp包接收时间戳及回包时间戳，均为大端序，用于计算延迟。时间戳单位是ms，8字节，起点无关但最好使用unix时间起点
- 状态反馈。

## 2. 数据传输阶段 (UDP Payload)
每帧音频数据发送 3 次冗余包：
| 字段 | 长度 | 说明 |
| :--- | :--- | :--- |
| **序号** | 1 Byte | 0x00 - 0xFF (循环递增) |
| **PCM 数据** | N Bytes | 原始音频采样数据 |

## 3. 冗余与处理
- **包三送**: 每帧数据连续发送 3 次相同序号的数据包。
- **接收端处理**: 结合 TCP 连接状态，丢弃重复及乱序包，利用序号进行丢包检测。
